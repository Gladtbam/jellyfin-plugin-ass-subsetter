# Jellyfin ASS Subsetter

**Jellyfin ASS Subsetter** 是一款专为 Jellyfin 打造的外挂 ASS 字幕字体子集化插件。

## 📖 项目简介

本插件致力于解决流媒体播放时“因客户端本地缺少字体导致字幕特效失效、排版错位”的痛点。通过服务端的实时优化，让客户端在**完全无需安装本地字体**的情况下，使用字幕所需字体，减少字体缺失造成的排版问题。

## ⚙️ 工作原理

* **路由拦截**：当客户端向服务器请求外挂字幕时，插件底层的 HTTP 中间件会瞬间拦截该请求。
* **物理裁剪**：按需提取字幕文本中实际用到的字形，减少随字幕下发的字体体积；实际大小取决于字体及字幕使用的字形。
* **动态封包与转码**：支持将精简后的字体通过 UUEncode 内嵌打包为 `.ass` 文件下发；支持通过 libass 实时渲染并编码为 `.sup` (PGS) 格式；也可将 ASS 与子集字体附件封装为实验性 `.mks`。
* **缓存调度**：处理完毕的成品字幕受 LRU（最近最少使用）机制管控，超出容量上限自动清理；同时支持在新片入库时后台静默预处理。
* **连播预取**：支持在用户观看剧集进度到达设定阈值（默认 85%）时，后台自动提取下一集的所有外挂字幕并进行子集化处理，实现无缝连播体验。

## 字体库存与恢复管理

字体库存保存在 Jellyfin 数据目录下 `ass-subsetter/ass-subsetter.db`。扫描会记录物理文件、字体面和别名，分析报告会保存重复候选、保留理由及替代关系。字幕处理通过已发布的内存索引查找字体，不会为每次字幕请求查询数据库。

### 发布代次与分析批次

* 文件或分析输入发生变化时，先构建待发布库存；只有完整扫描、重复分析及发布前校验成功，才一起发布新库存代次和新分析批次。
* 文件、影响判重的目录策略及分析证据版本均未变化时，沿用当前发布代次和分析批次。首次扫描、缺少有效分析或主动重建派生数据时会重新生成。
* 失败或取消的扫描、分析不会替换当前发布结果。分析期间文件或配置发生变化，会拒绝发布，需重新扫描；过期报告会显示失效原因，不能继续作为隔离授权。

相同文件哈希或同一族名不能单独授权隔离：字体必须可分类，且满足功能证据、目录策略和整文件替代验证。必要功能证据不完整或验证失败时不会自动隔离。

### 管理页面

在插件配置的“字体管理”中可使用以下页面：

| 页面 | 内容与操作 |
| --- | --- |
| 概览 | 已发布字体、最新分析结果、数据库健康和近期处理耗时 |
| 分析报告 | 查看字体比对、评分及保留依据，选择已验证可替代的文件进行隔离 |
| 隔离区 | 查看已隔离、待处理及失败条目，恢复隔离文件 |
| 文件名重命名 | 查看命名依据及目标路径，按待处理、已跳过、失败、已重命名和已回滚筛选，选择执行或回滚 |

重命名候选在分析发布时预先生成并存入数据库，页面按页读取，不在打开页面时计算全量命名结果。命名规则或候选上下文变化后，可通过“刷新重命名候选”重新生成；过期或尚未生成的候选不能直接执行。重命名不发布独立的计划批次，执行记录按文件状态展示。

隔离副本满 30 天后才具备清理条件，清理前仍会重新验证替代文件及当前路径安全性。恢复和重命名回滚不会覆盖目标位置已有的文件；目录保护、文件占用、链接或证据变化等安全检查未通过时，会跳过或阻止相应操作，并记录原因。Jellyfin 服务账号需要对涉及移动、恢复或删除的目录具有相应权限。

### 计划任务与互斥

Jellyfin“计划任务”中的字体维护任务默认安排如下，管理员可自行调整触发器：

| 任务 | 默认触发器 |
| --- | --- |
| 更新字体库存并分析重复字体 | 每 24 小时，无启动触发器 |
| 隔离重复字体 | 无，可在计划任务页点击“运行”或添加触发器 |
| 清理过期字体隔离项 | 每 24 小时，无启动触发器 |
| 字体文件名重命名 | 无，可在计划任务页点击“运行”或添加触发器 |
| 清理旧分析批次与字体库存代次 | 每 24 小时，无启动触发器 |

点击隔离或重命名任务的“运行”可直接批量处理符合条件的文件，无需先在管理页面选择；已有排队请求时优先执行。只想处理指定文件时，请在“字体管理”页面选择条目后执行。

历史报告与发布代次的保留数量默认为 3，设置为 0 表示全部保留。

所有字体任务（分析、隔离、恢复、过期清理、文件名维护及历史清理）共用一把任务锁，在领取请求之前获取，并在整个操作结束后释放。运行期间再次触发的 Jellyfin 计划任务会取消本次执行，可等待下一次触发或手动重试。

管理页面提交的请求按持久化授权执行，进度以页面请求及条目状态为准。宿主任务忙碌或启动尚未完成时，请求保持待执行并由后台重试；重试不会扩大已授权的操作范围。

## 🛠️ 技术架构

* **核心处理引擎**：通过原生 P/Invoke 深度集成 **HarfBuzz** 进行内存级子集化处理（已弃用 [MkvAutoSubset](https://github.com/MkvAutoSubset/MkvAutoSubset) 外部依赖），实现极速无损裁剪。
* **图形渲染引擎**：内建 **libass** 渲染层与纯 C# 实现的 PGS 编码器（AssToSupConverter），支持 ASS 到 SUP 格式的高效转换。
* **Jellyfin 插件端**：基于 **C# (.NET 9.0)** 开发，深度集成 ASP.NET Core 的依赖注入、路由拦截（Middleware）与后台常驻任务（IHostedService）。
* **字体持久化**：使用 **EF Core 9 与 SQLite** 管理库存、分析和维护记录，关键发布保持事务一致性。EF Core、SQLite 托管及原生运行时由 Jellyfin 主机提供，插件包不携带这些数据库运行时依赖。

## ⚠️ 已知缺陷与限制

* **SUP 实时转码延迟与性能开销**：将长篇 ASS 文本完整渲染并转码为 SUP (PGS) 属于极其耗时的 CPU 密集型任务。**如果播放时未命中缓存而触发实时转码，客户端可能需要等待较长时间（几十秒至数分钟不等，取决于服务器性能）才能加载出字幕，甚至导致客户端请求超时。**
  * **💡 补救措施**：强烈建议在插件配置中**勾选“开启自动扫描预处理”**与**“开启下一集字幕预取功能”**。通过提前在后台静默完成转码并写入缓存。
* **极端字体子集化失败**：极少数非标准构造的字体或受 DRM 版权保护限制的字体，在调用 HarfBuzz 进行子集化裁剪时可能会失败。
* **MKS 实验性模式**：配置中的“生成 MKS（实验性）”会复用 Jellyfin 配置的 FFmpeg，将重写后的 ASS 字幕轨与子集字体作为 Matroska attachments 封装，适用于 mpv 等兼容播放器。该模式必须由管理员手动启用，插件不会通过 User-Agent 或客户端能力自动选择；生成失败时遵循“异常时回退至原版字幕”配置。

## 🚀 安装与使用

### 手动安装

1. **安装**：将编译打包好的 `Jellyfin.Plugin.AssSubsetter` 文件夹放置到 Jellyfin 服务端的 `plugins` 目录下。
2. **重启**：重启 Jellyfin 服务进程。
3. **配置**：进入 Jellyfin 控制台 -> 插件 -> 选择 **ASS Subsetter**：
   * 配置存放字幕字体的物理目录路径（多路径使用分号分隔，如 `/media/fonts;/media/extra-fonts`）。
   * 勾选“开启自动扫描预处理”。
   * 勾选“开启下一集字幕预取功能”，并可自定义触发百分比。
   * 保存配置，并在“字体管理”中检查库存及分析状态；需要立即更新时执行“更新字体库存并分析重复字体”任务。
4. **播放**：打开带外挂 ASS 字幕的视频并选择字幕轨。字幕效果取决于字体是否齐全及客户端对相应字幕格式的支持；未命中缓存时需等待处理完成。


### 插件库安装

`https://gladtbam.github.io/jellyfin-plugin-ass-subsetter/manifest.json`

### 从源码构建

使用 .NET 9 SDK，在仓库根目录执行：

```sh
dotnet publish Jellyfin.Plugin.AssSubsetter/Jellyfin.Plugin.AssSubsetter.csproj -c Release
```

插件发布目录为 `Jellyfin.Plugin.AssSubsetter/bin/Release/net9.0/publish/`。将该目录内容部署到 Jellyfin 的插件目录后重启服务。当前项目按 Jellyfin 10.11.9 的依赖构建。

运行测试：

```sh
dotnet test Jellyfin.Plugin.AssSubsetter.Tests/Jellyfin.Plugin.AssSubsetter.Tests.csproj -c Release
```

使用 PowerShell 检查发布包中是否误带宿主提供的数据库运行时：

```powershell
./scripts/verify-plugin-artifacts.ps1 -PackagePath ./Jellyfin.Plugin.AssSubsetter/bin/Release/net9.0/publish
```
